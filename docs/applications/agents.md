# 工具与智能体

智能体可以建模为部分可观测环境中的策略：根据当前观察与状态选择行动，读取反馈，再决定是否继续。LLM 负责产生候选决策，但状态机、权限和终止条件应由系统明确实现。

## 基本循环

\[
o_t \rightarrow \text{state}_t \rightarrow a_t
\rightarrow \text{tool result}_t \rightarrow o_{t+1}
\]

[ReAct](https://arxiv.org/abs/2210.03629) 把推理轨迹与行动交错；[Toolformer](https://arxiv.org/abs/2302.04761) 研究模型自监督学习何时调用 API。具体产品不必复刻论文中的文本轨迹，关键是把行动接口与反馈语义定义清楚。

## 工具契约

每个工具应声明：

- 输入 schema、类型、范围和默认值；
- 幂等性、超时、重试与取消语义；
- 读取、写入、外部通信或破坏性等级；
- 身份、租户和最小权限；
- 成功、部分成功、失败与未知状态；
- 可验证的业务终态。

结构化输出保证语法，不保证参数正确、调用合理、权限充分或结果达成。

## 记忆

- **上下文记忆**：当前 prompt 中的短期状态。
- **工作记忆**：任务图、计划、工具结果和未决事项。
- **长期记忆**：跨任务保存的事实或偏好，需要来源、权限、更新和删除机制。

写入长期记忆前应区分用户明确授权、可靠来源和模型推断；检索时还需处理过期、冲突和隐私。

## 终止与恢复

循环必须有成功条件、预算、最大步骤、重复检测和不可恢复错误。长任务应持久化结构化状态，使重启后能判断哪些动作已执行，避免重复支付、重复发送或重复修改。

## 评测

除最终成功率外，记录步骤数、工具错误、无效调用、回滚、澄清质量、权限违规、成本和尾延迟。可执行任务应由环境状态判定，不以模型自述“完成”作为成功证据。
