# 知识架构

知识库按稳定问题组织，而不是按框架目录、模型热度或论文发布时间堆叠。具体模型和系统会更换，表示、目标、状态、计算与验证这些对象相对稳定。

## 十层主干

| 层 | 核心对象 | 向下依赖 | 向上影响 |
| --- | --- | --- | --- |
| 基础 | 概率、token、目标与缩放 | 数学与统计 | 所有训练和评测 |
| 数据 | 来源、序列、偏好与轨迹 | 目标定义 | 模型学到的分布 |
| 结构 | attention、MLP、MoE、位置 | tensor 与计算图 | 容量、缓存与稳定性 |
| 多模态 | encoder、接口、生成表示 | 结构与数据 | 视觉、音频、视频能力 |
| 训练 | optimizer、SFT、偏好与 RL | 数据和目标 | checkpoint 行为 |
| 系统 | 并行、kernel、数值与容错 | 训练计算图 | 可训练规模与效率 |
| 推理 | 解码、KV、调度与分离 | checkpoint 与硬件 | 延迟、吞吐与成本 |
| 应用 | 检索、工具、agent | 推理与外部状态 | 端到端任务能力 |
| 评测 | 协议、verifier、可靠性 | 所有上游对象 | 选择、门禁与迭代 |
| 谱系 | 版本、证据和公开事件 | 全部机制 | 时效性判断 |

一项新技术应先落到其中的稳定对象，再决定是否需要新页面。例如新的 attention kernel 通常进入系统层，并链接结构与推理；某个模型发布则先进入谱系，只有出现可泛化机制时才扩展原理页。

## 页面职责

### 总览页

回答“这层有哪些对象、怎样选择阅读路径”，保持短而稳定。

### 机制页

按动机、定义、计算图、系统代价、证据、失效和验证组织。公式必须说明变量，性能结论必须说明工作负载。

### 案例页

用于展示怎样应用通用框架，不承担概念的唯一解释。案例结论需要具体版本与日期，未知字段保持未知。

### 实践页

提供最小 reference、实验卡和调试顺序。示例优先保证语义可审计，再与优化实现比较。

### 索引页

术语、文献和更新日志负责发现与回溯，不复制正文。

## 结构演进

当一个页面同时承担多个可独立回答的问题时，应拆分；当多个页面重复同一机制、差别只来自模型名称时，应合并。结构调整遵循：

1. 先画主题覆盖与依赖图；
2. 确定每个概念唯一的 canonical page；
3. 保留旧入口为概览或迁移链接，避免深链突然失效；
4. 更新导航、正文交叉链接、术语与文献；
5. 检查孤页、重复标题和未纳入导航的页面；
6. 通过 Markdown、公式、代码、严格构建和浏览器渲染；
7. 再核验线上深链与移动端。

结构变化的目标是降低寻找概念与维护一致性的成本，不以页面数量为指标。

## 交叉链接 {#cross-links}

一条高质量链接应解释关系：

- “目标函数的数值实现见……”；
- “该结构改变的 KV 成本见……”；
- “在线系统中的对应状态见……”；
- “评测协议与已知失效见……”。

只写“相关链接”或在每页末尾堆一串入口，不能形成知识网络。稳定原理页优先互链，时效性案例不应成为基础概念的必经路径。

## 内容门禁

每次发布至少通过：

- 页面完整进入导航，无孤页；
- 内部目标与 fragment 可达；
- 外部资料优先原始论文或官方文档；
- 公式分隔符、括号、命令与浏览器 MathJax 正常；
- Python 示例可解析；
- 生成 HTML 无原始 TeX、未闭合 Markdown 或空链接；
- 桌面与移动页面无横向溢出；
- 未出现凭据、个人路径或非公开工作痕迹。

具体阅读纪律见[阅读方法](method.md)，来源与时效判断见[证据与研究方法](evidence.md)。
