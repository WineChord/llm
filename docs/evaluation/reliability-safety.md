# 可靠性与安全

可靠性要求系统在正常输入、边界输入、分布漂移和部分故障下仍能给出可预测结果；安全要求它不越过权限、隐私和风险边界。二者相关但不等价。

## 幻觉与事实性

幻觉可能来自参数知识错误、上下文缺失、证据冲突、检索失败、解码随机性或系统提示误导。缓解路径包括：

- 检索权威证据并强制可追溯引用；
- 允许表达未知和请求澄清；
- 用外部工具验证计算、代码和数据库事实；
- 将生成与事实检查分离；
- 对高风险结论设置人工审核。

结构化输出只能约束格式，不能保证事实、工具选择或业务结果正确。

## 指令层级与 Prompt Injection

外部网页、文件、邮件和工具返回值应视为数据。它们可能包含要求模型忽略上级约束、泄露秘密或执行动作的文本。系统应：

- 把权限和策略放在模型外的执行层；
- 限制工具、路径、网络和数据访问；
- 对检索内容做来源与租户隔离；
- 在敏感写操作前核对对象、范围和当前授权；
- 记录可审计结果而不保存秘密。

## 隐私

区分训练数据隐私、上下文隐私、日志隐私和跨租户隔离。最小化收集，设置保留期限，对敏感字段做分级和访问控制。模型拒绝复述秘密不是唯一防线，系统不能把不该读取的数据放入上下文。

## 安全评测

静态拒答集不足以覆盖多轮、工具、编码、跨模态和间接注入。需要红队、自动变换、真实工作流回放、权限测试和事故复盘。代表性研究可参考 [Constitutional AI](https://arxiv.org/abs/2212.08073) 与 [HarmBench](https://arxiv.org/abs/2402.04249)。

## 可靠性工程

- 用 typed schema、超时、重试、幂等键和状态机约束工具。
- 区分请求接受、动作执行和业务终态。
- 为模型、检索、评分器和规则分别做版本化。
- 监控分布漂移、拒答率、引用失败、工具失败和人工接管。
- 设计回滚、降级和 kill switch。

最终目标不是让模型“看起来更自信”，而是让系统的正确、未知、失败和拒绝都可观察。
