# 评测与可靠性

评测是对“某个版本的系统，在某个分布、协议和指标下表现如何”的估计。榜单不是模型本体属性，分数脱离 prompt、解码、工具、数据污染和评分器就不可解释。

## 四层评测

1. **模型层**：损失、知识、推理、代码、多模态与安全行为。
2. **组件层**：检索、reranker、工具选择、缓存、量化与 guardrail。
3. **系统层**：端到端任务成功、权限、可靠性、延迟和成本。
4. **真实运行层**：用户分布、反馈、事故、漂移与业务结果。

## 基准类型

- 静态题集适合可重复比较，但容易污染和饱和。
- 动态或私有题集更新更快，但透明度与复现较弱。
- 人类偏好能测主观质量，但成本高且标注者差异大。
- LLM-as-a-judge 可扩展，却存在位置、长度、风格与自偏好。
- 可执行验证适合代码、数学和结构化任务，但覆盖面有限。

## 最小报告

模型与 checkpoint、prompt/template、few-shot、解码、工具、上下文长度、数据版本、样本数、评分器、重复次数、置信区间、失败分类和核验日期。
