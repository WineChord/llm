# 评测设计

好的评测从决策问题出发：它要选择模型、验证改动、守住回归门槛，还是估计线上风险。不同目的需要不同数据与统计功效。

## 数据切分

- 开发集用于调 prompt、阈值和路由，不可再当无偏测试。
- 测试集应冻结并控制访问，记录污染风险。
- 按时间、语言、领域、难度和用户群分层，避免平均分掩盖薄弱群体。
- 对开放式任务保存原始输出，便于评分器升级后重评。

## 指标

准确率适合单标签题；pass@$k$ 适合多次采样的可执行任务；pairwise win rate 适合偏好比较；校准需要把置信度与实际正确率对齐。任何指标都要说明分母与无效样本如何处理。

若独立伯努利试验成功概率为 $p$，采样 $k$ 次至少成功一次的理想概率为：

$$
1-(1-p)^k
$$

真实样本相关，不能用此式替代实测 pass@$k$。

## 统计

- 对样本级差值做 paired bootstrap，通常比比较两个独立均值更有效。
- 报告置信区间，不把小于噪声的差异写成结论。
- 多 benchmark 同时调参会产生选择偏差。
- judge 模型升级会改变历史分数，应保留版本并做桥接评测。

## 代表性基准

- [MMLU](https://arxiv.org/abs/2009.03300)：多学科知识与问题求解。
- [GPQA](https://arxiv.org/abs/2311.12022)：研究生水平、设计为较难检索的问答。
- [SWE-bench](https://arxiv.org/abs/2310.06770)：真实仓库 issue 的代码修复。
- [MT-Bench 与 Chatbot Arena](https://arxiv.org/abs/2306.05685)：对话评测与人类偏好。
- [MMMU](https://arxiv.org/abs/2311.16502)：多学科多模态理解与推理。

这些基准测量的对象和年代不同，不能合成一个无条件“智能分数”。
