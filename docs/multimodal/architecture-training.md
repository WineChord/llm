# 多模态融合与训练

多模态架构可以按“预训练组件冻结多少”与“模态多早融合”理解。

## 常见接口

### Projector

线性层或 MLP 把视觉 encoder 输出投影到 LLM hidden size。实现简单、适合两阶段训练，但模态交互主要依赖 LLM 后续层。

### Querying 或 Resampling

固定数量的可学习 query 从高分辨率特征中提取信息，控制送入 LLM 的 token 数。[BLIP-2](https://arxiv.org/abs/2301.12597) 的 Q-Former 是代表。压缩提高效率，也可能丢失小目标和细粒度文字。

### Cross-Attention

在语言主干中插入对视觉或音频特征的 cross-attention。[Flamingo](https://arxiv.org/abs/2204.14198) 通过 gated cross-attention 处理交错图文。接口表达力更强，但会改变主干结构和 checkpoint 兼容性。

### 统一离散序列

把不同模态编码为统一 token，由一个自回归模型同时理解与生成。它统一了目标函数，却把 tokenizer、序列长度、模态竞争和连续信号重建都带入同一系统。[Chameleon](https://arxiv.org/abs/2405.09818) 展示了 early-fusion token 模型的一条路线。

## 训练阶段

1. **模态对齐**：固定主干，训练接口把感知特征映射到语言空间。
2. **多模态预训练**：使用图文、交错文档、视频文本或音频文本目标。
3. **指令微调**：训练问答、grounding、OCR、工具使用和多轮交互。
4. **偏好与安全训练**：控制幻觉、拒答、敏感内容和跨模态攻击。

阶段边界不是固定标准。报告配方时应说明哪些组件冻结、各阶段数据量、分辨率、序列打包、损失权重和可训练参数。

## 分辨率与 token 预算

固定 resize 容易丢小字；动态切片或多尺度输入保留细节，但 token 数和 prefill 成本增长。需要联合优化：

- 原图缩放与 patch 大小；
- 全局缩略图与局部 crop；
- 视觉 token 压缩；
- OCR 或检测工具旁路；
- 多图、视频帧和文本之间的预算。

## 常见失效

- 看似合理的描述掩盖了未读取图像的语言先验。
- 文本指令与图像内恶意文字发生权限冲突。
- 图像裁切改变答案，暴露空间鲁棒性不足。
- 训练集答案风格泄漏到自动评分器。
- 多图顺序、帧采样或模态占位 token 与推理模板不一致。

多模态 benchmark 需要按能力拆分；代表性综合评测可参考 [MMMU](https://arxiv.org/abs/2311.16502)。
